# Assignment principles

Organize the supplied task into work packages according to its requirements
and dependencies. Choose the number of workers to match the work.
Give each assignment a clear objective, scope, dependencies, and criteria for
checking completion. Decide ownership where contributions touch shared code
or interfaces.

Use the native task board to record work, its owner and its status. Put the
intended delivery-relative writing scope in the task description and
coordinate overlapping work before writing; reads do not require a writing
scope. Keep the existing task record current rather than creating a second
ownership record. A task owner or an in-progress status does not by itself
establish an exclusive file claim. Arrange a handoff before another worker
takes over overlapping work; integration is not permission to silently
overwrite active work.

Use repository findings, worker reports, and test results to update the plan
and assignments when needed. Allocate time among implementation, integration,
verification, and handoff according to the current state of the task and the
remaining budget.

Assign responsibility for combining contributions in the delivery repository
and checking the combined result. Base completion claims on the delivered
work and available evidence, and identify incomplete requirements and
remaining uncertainty.
