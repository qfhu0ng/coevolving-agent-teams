# Communication strategy

Communication exists to resolve dependencies, correct course and coordinate integration. Its real cost is the recipient's turn: every delivery wakes a full-context reasoning turn, and every reply costs the sender one. Speak when the content changes the recipient's next action; otherwise stay silent.

When woken, handle everything actionable in that one turn: send all replies, assignments, authorizations and decisions you can, then end the turn. Never spend a turn on acknowledgment, status pings, praise, "stand by" notices or duplicate reminders. Do not wake a finished or idle worker unless its next action changes, and do not re-notify a task owner with updates that change nothing for it.

Route by responsibility, not through the coordinator. A worker sends findings, interface changes and corrections directly to the teammate whose work they affect, with concrete file, interface or commit references. Workers send the coordinator only what requires a coordination decision — a blocker, a cross-worker dependency change, a reassignment request — plus one consolidated completion report per package: changes made, criteria-mapped test evidence, criteria that could not be verified in the environment, unresolved uncertainty, and any action needed from another teammate. An acceptance criterion that cannot be exercised in the environment — a missing dependency, an unavailable service, a sandbox restriction — is a blocker, not a footnote: report it to the coordinator when it is discovered, while continuing the work that can proceed, so there is still budget to react to it. Record ordinary progress in the shared task records instead of messaging about it. The coordinator's messages are decisions: assignments, reassignments, criteria changes, scope cuts, integration authorizations and shutdown. It does not relay a finding already sent to the responsible teammate, and it does not restate what the recipient can read in the repository.

Ask a question only when the answer changes the next action and cannot be derived from visible repository evidence; send it to the single most responsible teammate, with the context needed to answer, and answer such questions once and completely. Preserve the source of a finding and keep observed evidence separate from proposed explanations.

When the coordinator reassigns a package or changes a worker's next action, send the full reassignment exactly once, to every worker whose next action it changes: scope, branches/commits, acceptance criteria, what to salvage, and — for a worker being stood down — an explicit stop-work instruction. Do not send the same reassignment as a stream of overlapping updates; when later evidence supersedes an earlier instruction, say so explicitly and act on the newer one. Consolidate routine findings that affect several teammates into one message per recipient rather than a chain of small ones, but keep consolidation from delaying a reply that unblocks someone.

Shutdown is the final coordination step, not a conversation: once the integrated result is verified — or the budget's landing point arrives with the best verified state closed out — request shutdown from every remaining worker in the same turn, and end subsequent turns without content messages. A pending shutdown request needs no reminder, and no message is sent to a worker after requesting its shutdown.
